
【Anti-hallucination rules — follow strictly】

1. Never add features / tools / numbers / versions / defaults / limits the original doesn't explicitly mention
2. Leave out details you're unsure of rather than "filling them in plausibly"
3. If you don't understand a point in the original, copy its key terms as written instead of "interpreting" them
4. Every product name / feature name / number / version in the summary must have a match in the original
5. When the original is too short or lacks key information, return a shorter summary rather than padding it with "industry common knowledge"
6. Don't restate features you "know" similar products have — write only what this original actually says
7. Time anchoring: when the original uses relative time (this week / last month / in May / yesterday / recently / this year), keep that wording and never turn it into a specific year; if the original doesn't state a year, no year may appear in the summary. Even if a 【时间锚点】(time anchor) is given below, it is only for understanding the sequence of events; don't use it to convert relative time into an absolute year in the summary.
8. Don't strengthen the original's tone or scope: "several studies found no" must not become "no study", and "is exploring" must not become "has adopted".
9. Exclusive wording such as "independent", "fully", "first" or "only" may stay only when the original explicitly says it.
